## Deviations and decisions (flagged for the checker)
1. **Vendor name is not shown.** `catalog.vendors` has no client grant or policy (the column grant with a policy was WO-0108, culled), and WO-0103 may not use the secret key or add a migration. `/vendor/account` shows "The vendor name is not shown in this build." and reads the name through `ownVendor` so it appears as soon as a grant exists. A migration (`grant select (id, name)` + policy "own vendor") is needed to meet CC7 literally; owner/orchestrator decision.
2. **The vendor header lives in `components/Nav.tsx`, not in `app/vendor/layout.tsx`.** The root layout always draws `Nav`; a second header in the vendor layout would repeat the Demo label and show the consumer links. The layout holds the local-backend sentence. `/vendor/gaps`, `/vendor/reports` (nav links) do not exist until WO-0106 (404 until then).
3. **One existing list extended, nothing loosened or removed:** `lib/supabase/source.test.ts` (the inventory of `location.assign` sinks gets `components/vendor/AgreementForm.tsx: location.assign('/vendor')`). `components/outfits/outfits.test.ts` is outside this work order's scope and was NOT touched: `lib/vendor/*.ts` take their client type from `../supabase/browser` (type only) instead of importing `@supabase/supabase-js`, so the suggestion-path import scan passes unchanged.
4. The existing gate assertion "a vendor is held, not let through" (role vendor with no vendor facts is `not_available`) still holds unchanged. No CSS or token was added, so `design.test.ts` and `contrast.test.ts` need no extension.
5. `VENDOR_AGREEMENT_VERSION` is `1` while the legal file says version 0.2 (R7 document point O2, owner's); the page does not print a version.
6. Vendor events are not recorded anywhere yet (dashboard and report screens do that, WO-0105/0106); only the types exist.
