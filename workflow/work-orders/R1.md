# Release R1: Engine core (spec and work orders)
Date: 2026-11-04
Requested by: product owner delegation of 2026-11-04. Workflow v0.4. Conventions: see R0.md ("Project conventions"). Branch: release/R1 (cut from main after R0 is merged).

## Goal
`packages/rules` is a pure TypeScript recommendation engine that, for any wardrobe, occasion, season and hemisphere, returns up to three valid, ranked, explained outfits (or says what is missing), the same way every time.

## Completion conditions (all machine-checkable)
- CC1: `bash workflow/gates/gate.sh` exits 0.
- CC2: `npm test -w @sparta/rules` exits 0 with at least 60 test cases.
- CC3: a fast-check property test over at least 200 random wardrobes x all occasions x all seasons proves: every suggestion passes R1, R2 and the slot structure (a top, a bottom, footwear); no item appears twice in an outfit; at most three suggestions; the result is identical when the input item order is shuffled (FR-58).
- CC4: a test proves `weights_base` in `packages/rules/data/rules.json` is rule_fit 0.50, occasion 0.20, completeness 0.10, condition 0.10, favourites 0.10 and sums to 1.
- CC5: every suggestion has at least one reason and every reason comes from the fixed templates (R8); a thin wardrobe returns `{ missing: [...] }` naming the missing slots (FR-54).
- CC6: a test greps `packages/rules/src` and proves it imports nothing from `node:*`, `fs`, `window`, `document` or any network API (browser-safe, FR-59).
- CC7: a timing test proves `suggest` on a 500-item wardrobe takes under 300 ms median over 20 runs on this machine.
- CC8: `npm run review-pack -w @sparta/rules` writes `workflow/evidence/R1/review-pack.md` with at least 50 suggestions from 5 named synthetic wardrobes (each suggestion: occasion, season, items, score and its parts, reasons).
- CC9: swap choices: a test proves every choice returned by `swapChoices` keeps the outfit valid under R1, R2 and the slots, and that the order is by `0.6*shape + 0.4*colour` with ties by item ID (shape falls back to sub-type equality because no embeddings exist yet).

## Scope fence
- Will NOT touch: apps/*, supabase/*, services/*, ml/*, docs/*, legal/*, packages/taxonomy/** (read-only dependency; request changes through the orchestrator).
- Will NOT do: the pairing part, Complete the look, Wardrobe unlock, learned parts (R4); any UI (R3).

## Glossary
- "valid" means passes R1 (occasion), R2 (season) and the slot structure of FDD 14.1.
- "wardrobe" means an array of items shaped as in LLD 9.5 (`Item`), which the engine receives as plain data.
