## Project conventions fixed for the whole build (agentic-os "project overrides")
- Diff limit: at most 500 changed lines per work order, not counting `package-lock.json` and JSON data files. Larger work is split before it starts.
- Approvals: the product owner delegated all approvals on 2026-11-04. Sensitive paths (CI config, migrations, auth) are still routed to an Opus checker; the delegation is logged in the work order.
- Dependencies approved by delegation, by name and why (anything else needs a new line here first): typescript (type checking), vitest (tests), eslint with typescript-eslint and @eslint/js (lint), fast-check (property tests for the engine), tsx (run TS scripts). Later releases add: next, react, react-dom and their @types (web app, R3).
- No tests may be edited, weakened, skipped or deleted to pass a gate.
- Environment limits found on 2026-11-04: Node 22 and npm 11 exist; Docker, the Supabase CLI and torch do NOT. Anything needing them is written but not claimed as verified.
- Standing rules of the workflow doc section 10 apply (stay in the repo and the named dataset folders; no Claude trailer in commits; no brute-force searches; time-box 10 minutes per investigation).

## Scope fence
- Will NOT touch: docs/*, legal/*, data/*, submissions/*, flow-diagrams/*, supabase/* (no database work in R0), services/*, jobs/*, ml/*, apps/* (R3).
- Will NOT do: the engine (R1), any UI, any database migration, the SQL version of `catalog.colour_family` (R2), models or H&M data work (R4).

## Glossary
- "gate" means `bash workflow/gates/gate.sh` and nothing else.
- "colour family function" means a pure TypeScript function `colourFamily(r,g,b)` that implements the LLD 4.3 algorithm (sRGB to CIELAB, CIE76 nearest reference swatch, first-listed swatch is the family's reference) using the swatch list in the LLD 4.3 seed, plus `rgbToLab`. It must also return `null` for null inputs and `'Multi'` is handled by callers, not by this function.
