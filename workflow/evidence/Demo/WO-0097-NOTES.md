# WO-0097 notes: demo data pack, start script and demo script (Release 0, as trimmed by the cull of 2026-11-12)

## Built
- `supabase/scripts/demo-data.sh` (+ `--counts`, `--remove`): refuses a non-local database URL AND a non-local auth API; runs `seed-demo-catalog.sh` and `seed-demo-insights.sh`; then 3 consumers by the local auth admin API (`email_confirm`, invitation row first):
  `demo-rich` (60 items, 15 purchases, 4 planned wishlist entries, consent, documents, onboarding with the real `app.complete_onboarding`), `demo-thin` (12 items: tops, bottoms, footwear only, 2 purchases, onboarded), `demo-new` (no items, consent and documents done, onboarding NOT done: "Start from popular items" is a button of the onboarding form, so the account must stop before it).
  Wardrobes are generated in SQL by fixed arithmetic (no randomness, ids = md5 of owner and index), invented names/brands, INR prices, no Activewear or Ethnic wear (so the vendor demo's hidden segments stay hidden).
- Vendor: the insights seed leaves a BARE `vendor-demo@example.test` auth row (no instance_id, audience or token strings), which the auth API reports as "user not found". The script first gives that row the shape the API gives its own users (one UPDATE), then sets the password through the admin API PUT. Never a second user with that email. `--remove` sets its password to null again so the insights seed's own `--remove` deletes it.
- Deviation: the insights seed accepts the vendor agreement for that account; the walk-through shows the agreement step, so `demo-data.sh` deletes that acceptance row at the end (a re-run puts the state back). `--counts` therefore shows `acceptances=0` after demo-data.
- Secrets: passwords from `openssl rand`, printed once (the last lines of the run), stored nowhere (no credentials file written: the optional git-ignored file was not needed). The secret key is read from `supabase status -o env` into shell variables and reaches curl through `-K -` on stdin (no argument).
- `workflow/demo/start-demo.sh` (+ `--no-login`, `--stop`): keys from the status command into the server's process environment only (build gets only NEXT_PUBLIC values; the secret key is server runtime only, needed by Leave the pilot's file removal); build under `timeout 900`, server under `timeout 7200` (its process group), free port by binding port 0, readiness = exit status of curl, state (pid port mode) in `$TMPDIR/sparta-demo.state`, removed by `--stop`.
- `workflow/demo/DEMO-SCRIPT.md`: 12-step table with times, say/proves, known limits as in the cull, reset and exact start order, both modes.
- `supabase/scripts/demo-data.test.ts`: 14 pure tests (7 bad URLs x 3 modes, no-secret and no-credentials-file text checks, synthetic-only, idempotence by construction, start-demo checks, DEMO-SCRIPT contents) + 1 live test (`SEED_LIVE=1`): two runs identical counts (cube_rows excluded: the first run aggregates before the three accounts exist), passwords printed once, `--remove` clears all.
