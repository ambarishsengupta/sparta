# R2c WO-0061 notes: pages, export download, leave-the-pilot flow

## What was built (apps/web)
- Settings (`/settings`, ready people only): display name, hemisphere, currency and occasions editable (the four columns the database grants); country shown, not editable; sharing shown locked ON with the FR-61 wording; Export my data; Leave the pilot (link); sign-out.
- About (`/about`, public): who runs the pilot, contact address from `NEXT_PUBLIC_CONTACT_EMAIL`, region from `NEXT_PUBLIC_HOSTING_REGION` (empty or invalid: the page says "not configured in this build"), countries from `app.supported_countries()`, the "When the pilot ends" paragraph pulled from section 7 of the Privacy Policy, links to Privacy, Terms and the notice. `/notice` is a new public page with the notice text.
- `/privacy` and `/terms` render `legal/*.md` through `lib/markdown.ts` (parser to a typed tree) and `components/legal/Markdown.tsx` (tree to elements). No HTML is read; every text is a React text child; links only to http(s) without credentials or to this site (`PRIVACY-POLICY.md` and `TERMS-OF-USE.md` map to `/privacy` and `/terms`); images become their alt text. Bounded work (200,000-character cap, a shared work budget, bounded scans). `components/legal/files.ts` finds `legal/` by walking up from the working directory; with the local backend the pages are prerendered at `next build` (static), with the Supabase backend they render on request and `outputFileTracingIncludes` ships the two files with the server output (checked in the `.nft.json` of /privacy, /terms and /about).
- Export (`ExportButton`): `app.export_my_data()` over the signed-in session, shown as a download built from a Blob; file name `sparta-export-YYYY-MM-DD.json`.
- Leave the pilot (`/leave`, `LeaveForm`): password typed again, a fresh `signInWithPassword` (re-authentication), then `app.delete_my_account()`, then local sign-out and removal of every `sb-` cookie, then `/goodbye` (public, no data). A wrong password never reaches the delete call.
- Not-available page: Export, Leave and Sign out (FR-4).
- Gate: `/goodbye` public; `/leave` reachable at every gate step except unconfirmed email; `/settings` for ready people only. Proxy decides `/goodbye`, `/about`, `/notice` before the session call (work during an outage).
- Shell: footer links (About, Privacy, Terms), Settings in the main nav when signed in.

## Judgements
- "Escape every character first": the reader builds a tree and React escapes text on output, instead of producing an HTML string, because an existing test forbids `dangerously...` anywhere in apps/web. The effect is the same and is tested with hostile input (script tags, `javascript:` and `data:` links, event attributes, nested HTML, entities, control characters, 200,000-character inputs, a property test over random text).
- Cookies are cleared in the browser (supabase sign-out with scope local, then every `sb-` cookie expired), not by a server route, so no new route and no new redirect sink exist. If the sign-out call fails the sweep still removes the cookies.
- The `app.delete_my_account()` result `already_deleted` counts as success. A failure after the call started is reported as "could not confirm the result", never as "nothing was deleted".
- Placed in `components/account/` and `components/legal/` instead of `lib/` for the modules that import `@supabase/supabase-js` or `node:fs`, because the suggestion-path tests require every file of `lib/` to import only React, Next links and the workspace packages.

# WO-0062 notes (R2c fix loop 1)

## What changed
1. **Re-authentication in the database (F1).** Migration `20261106100000_wo0062_reauth_audit_log_and_profile_check.sql` makes `app.delete_my_account()` refuse with `42501 reauthentication_required` unless the signed token's top-level `amr` list has an entry with method `password`, `otp`, `oauth`, `magiclink` or `sso/saml` whose numeric `timestamp` is within `ops.settings.reauth_window_seconds` (seeded 300; missing or non-numeric means 300) and not more than 60 seconds ahead. Any malformed shape is a refusal. Real GoTrue claims were inspected first: a password sign-in carries `amr: [{"method":"password","timestamp":<epoch seconds>}]`; a refreshed token keeps the original timestamp (a refresh does not renew re-authentication); the sign-up confirmation link carries `email/signup`, which is not on the work order's list, so a confirmation session never qualifies, fresh or stale (the person types the password, which the app does anyway). The app maps the message to "Please enter your password again. Nothing was deleted." and keeps the fresh sign-in before the call.
2. **Auth audit log (F2).** The same function deletes every `auth.audit_log_entries` row whose payload text contains the user id or the e-mail address (any case), also on the `already_deleted` retry (id only). It is a plain substring test, so an entry that mentions a longer address ending in this one (joann@x.test for ann@x.test) is removed too: a deliberate over-deletion, preferred to leaving the address. **To verify at deployment:** the hosted Auth setting that stops writing this log (LLD "Logs") is switched off; the function is the fallback the LLD names.
3. **Held pages (F3).** `HeldOptions` (Export my data, Leave the pilot link, Sign out) is on the pilot-notice and accept-terms pages. The pinned link list of the notice test now includes `/leave` on purpose.
4. **Renderer time (F4).** `lib/markdown.ts`: the quadratic closing-hash pattern is a loop. Two more quadratic patterns were found and replaced by loops with identical meaning (proved by a property test against the old patterns): the heading pattern `^(#{1,6})\s+(.+)$` and the list-item pattern, both slow when a long run of white space is followed by U+2028 or U+2029 (`.` does not match them): 40,000 tabs then U+2028 took 10 s, 100,000 spaces 4 s. The old closing-hash pattern took 38 s on 199,000 spaces. Now 1 to 10 ms. The comment's "work budget" claim was reworded to what is true: look-aheads for a closing mark spend one shared budget, everything else is one linear pass.
   Regexes checked for nested or repeated quantifiers: safeHref x3 (scheme, allowed characters, the `./`-prefixed file name: its only repeated group is anchored, unambiguous, applied to at most 2,000 characters), the backslash-escape test, slugify x2 (after the first replace no run of dashes remains), RULE, QUOTE (anchored, `.*` at the end, linear), isSeparator, `^[ \t]{2,}\S`, the digit tests, the `\s+` split of a link target, the CRLF and tab replacers, `Markdown.tsx` isSite, `files.ts`. Each worst input is timed in `markdown-time.test.ts` (limit 200 ms); a test also scans the source for repeated groups and fails on any new one.
5. **Tests (F5, F6).** 008 now: asserts B exists and D does not (and A/B the other way, plus an X/Y pair deleted in the other order); exports with claims naming B in `user_metadata`, `app_metadata` and top-level claims return only the caller's document; every function without arguments (found from the catalog; the list is pinned) answers the same with and without those claims, for A and for a vendor W whose answers differ from B's. Cookie expiry Path/Max-Age for every `sb-` cookie (A01, with a cookie-jar model of the path rule), the closeParen and find budgets (A19), closing hashes (A21).
6. **Browser-only data (item 7).** `clearBrowserUsage()` removes every key starting `sparta.events.` or `sparta.settings.` (today `sparta.events.v1`, `sparta.settings.v1`); it runs when the Leave form succeeds and on every Sign out (`SignOutForm`, one client component used by Nav, Settings, Not available and the held pages; it never cancels the post, so sign-out still works without scripts). **Not cleared:** `sparta.wardrobe.v1`, the device-local wardrobe of the no-account mode: it is not usage data and the account flow does not own it. A test lists every `sparta.*.vN` key in the source so a new key forces a decision. Privacy Policy section 11 ("removed when you sign out or leave the pilot") is now true for the usage log.
7. **No profile row (item 8).** `delete_my_account()` now refuses (42501) when the auth user exists but has no profile row; a token for a user that no longer exists still answers `already_deleted`. `export_my_data()` already refused without a consumer profile; 008 tests both.
