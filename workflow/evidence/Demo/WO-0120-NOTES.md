# WO-0120 notes: H&M demo catalogue loader (local only)

Files: `workflow/demo/hm/load_hm_demo_catalog.py` (stdlib Python, 148 lines), `mapping.json` (hand-written), `tests/test_load_hm_demo_catalog.py` (14 tests) and `tests/articles.csv` (INVENTED fixture, ids 099xxxxxxx, names "Zzyx ..."), `.gitignore` (+ `workflow/demo/hm/out/`). No migration: the existing `catalog.catalog_items` columns suffice (sku, name, brand, category, sub_type, colour_r/g/b, product_url; price, gtin and currency stay null).
Run: `~/.sparta-venv/bin/python workflow/demo/hm/load_hm_demo_catalog.py [--count N] [--remove] [--counts] [--db-url URL]` (default 1500, local database only, docker exec fallback, exit 2 for a refused URL or a missing folder).
Behaviour: Menswear rows of a mapped type whose photo `images/<first 3 digits>/<id>.jpg` exists (checked file by file, never opened) -> even split across categories (a small category gives its unused share to the larger ones), seeded shuffle per category (seed 20261112) -> one source `hm-demo` (allowed = false) and active items, sku = article id with its leading zero. Re-running with the same or a smaller count leaves exactly N items (stale hm-demo items are deleted). `--remove` deletes the hm-demo source only; items go with it by the foreign key and users' items lose only the link.
Real data (read at run time, nothing stored): 12,553 Menswear rows, 11,029 of a mapped type with a photo. 29 H&M types mapped to 7 categories (Tops, Bottoms, Outerwear, Footwear, Accessories, Underwear and socks, Occasion wear) and 24 sub-types; the rest skipped (Swimwear bottom, Other shoe, Hat/beanie, Sunglasses, Top, Hat/brim, Other accessories, pyjamas, Gloves, jewellery, Unknown, Slippers, Wallet, Flat shoes and others). Colour: each of the 49 H&M colour groups maps to a family of `jobs/collector/mapping/colour.json` (its reference RGB; "Dark Blue" -> Navy, "Dark Red" -> Maroon); Transparent, Other and Unknown stay null.
Live run (local stack): `--count 1500` -> 1,500 active items (246 each in Tops, Bottoms, Outerwear, Accessories, Underwear and socks; Footwear 245; Occasion wear 25), 1,500 distinct skus, 1 without colour; `--remove` -> 0 items, 0 hm-demo sources; the synthetic `demo` source (40 items) untouched.
Mutants (scratch copy outside the repo, removed): no water-filling, guard `match` instead of `fullmatch`, no Menswear filter, no photo check, no quote escaping: all 5 killed.
Not collected by the gate: the tests are pytest (no vitest or collector_tests path covers workflow/demo/hm). Run them with `~/.sparta-venv/bin/python -m pytest workflow/demo/hm/tests -q`; `SEED_LIVE=1` adds the live test. To collect them a line would be needed in `workflow/gates/collector_tests.sh` (e.g. a second pytest call on workflow/demo/hm/tests), which is outside this WO's scope.
Known older finding the repo scan tolerates: submissions/D3 holds five real-looking article ids (legal review item 20); the scan fails only for a tracked file with 20 or more distinct ids.
