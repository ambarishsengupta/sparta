# Decision (orchestrator, after the WO-0070 security review, 2026-11-06)
LLD 6 and 7.1 give the worker no direct storage privilege: it gets signed URLs from `/api/worker/signed-urls`, and account deletion removes storage objects through the Storage API with the secret key BEFORE the database function (the reviewer proved that deleting only the rows leaves the file bytes behind with nothing pointing at them: MAJOR-1). So a small server-only admin module is built; this deliberately relaxes the earlier blanket 'no service key in apps/web' rule to 'only in apps/web/lib/server/admin.ts', with tests that keep it out of every client bundle.

# Work Order WO-0074: WO-0071 review follow-ups (limiter order and test hardening)
Action: execute. Owner: Frontend maker. Checker: orchestrator gate; Spec QC pass at the end of R5b.
In scope: apps/web/**, workflow/gates/**, workflow/evidence/R5b/**
Note: no change to supabase/*, packages/*, services/*. Defensive in-process and unit tests only; do not write attack tooling.
Instructions (each with a test that fails on the old behaviour, shown by scratch-copy mutation outside the repo):
1. MAJOR (confirmed by reading the code in two review passes): in `apps/web/lib/server/signed-urls.ts` the per-process rate limiter counts a request BEFORE the bearer token is checked, so unauthenticated traffic can exhaust the real worker's 120/min budget. Fix: check the token first (constant-time), count only requests that fail authentication in a separate small limiter (for example 30 failures per minute per process, then answer 429 to failures only, never to a correct token) and count successful calls in their own budget; the real worker is never locked out by failures. Unit tests with an injected clock and limiter: 500 unauthenticated requests then an authenticated one succeeds; failures are throttled; correct-token budget works; no timing difference between wrong-length and wrong-value tokens in the code path (compare hashes).
2. MINOR-1: `apps/web/lib/server/build-output.test.ts` skips silently when `.next` is absent, so the gate never runs the containment check. 3. MINOR-3: the importer pin in `apps/web/lib/supabase/source.test.ts` matches only single-quoted `from '...'`: extend it to double quotes, template-less dynamic `import()`, `require(`, `export ... from`, and re-export chains; tests with synthetic offending source strings for each form.
4. MINOR-4: `apps/web/test-support/stack.ts` lock: refresh the lock directory's mtime while held (every 10 s with an unref'd timer, cleared on release) so a long suite is never taken over after 60 s while another waits up to 100 s; test with a fake clock.

MINOR-5: the Origin check in `apps/web/lib/server/purge.ts` compares host only: compare scheme, host and port (full origin) against the request's Host/forwarded values correctly (the earlier bug: `request.url` host differed from the browser's Host header: keep comparing against the Host header, add the scheme from the forwarded proto or the configured public origin); tests for http vs https mismatch, port mismatch, null Origin, missing Origin (allowed only with the same-site fetch metadata `Sec-Fetch-Site: same-origin` or `none`).
