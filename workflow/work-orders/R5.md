# Release R5a: Garment model version 1 (spec and work orders)
Date: 2026-11-04
Requested by: product owner delegation of 2026-11-04 (and the owner's override of the weekly 90% stop for this week). Workflow v0.4; conventions in R0.md. Branch release/R5 (from main).
Scope note: only the OFFLINE model part of R5 (training, evaluation, export, model card, committed ONNX file). The FastAPI worker, job queue, background removal and the item-form pre-fill need Docker, Postgres or Supabase and are NOT built here (R5b). Dependencies approved by delegation: torch, numpy, onnx, onnxruntime, pillow (CPU), installed in a virtualenv OUTSIDE the repo whose python is `SPARTA_VENV_PYTHON` in workflow/local.env; exact versions pinned in ml/recommendation-engine/requirements.txt.

## Goal
`services/worker/models/garment-cnn-v1.onnx` exists, trained only on the Fashion-MNIST IDX files, with a reproducible evaluation, a model card and a tested preprocessing identical for evaluation and the worker.

## Completion conditions
- CC1: `bash workflow/gates/gate.sh` exits 0.
- CC2: `$SPARTA_VENV_PYTHON -B -m unittest discover -s ml/recommendation-engine/garment/tests` passes (at least 25 tests): preprocessing golden outputs on 10 synthetic fixture cut-outs (generated by code, not H&M and not team photos), every `class_map.json` value exists in packages/taxonomy (category and sub-type), Dress maps to none, the IDX reader checks magic numbers and counts, a test that the training code reads only the IDX files and never the CSV files (source scan), the model has the documented shape (about 26,000 weights; two outputs: 10 scores and 32 numbers).
- CC3: `train.py` (seeded; 54,000/6,000 stratified train/validation split of the 60,000 IDX training pictures; test pictures untouched until the final report; early stopping on validation) then `evaluate.py` report accuracy on the 10,000 IDX test pictures overall and per class, and a confusion matrix, computed by running the exported ONNX file with onnxruntime. Aim: about 90% or more overall; report the real number; never tune on the test set; if below 0.85 say so plainly in the card.
- CC4: `export_onnx.py` writes `services/worker/models/garment-cnn-v1.onnx` (under 1 MB) with two outputs; onnxruntime matches PyTorch within 1e-4 on 100 test pictures (checked and logged by the script and by a test that skips with a clear message only if the file is absent).
- CC5: `ml/recommendation-engine/garment/model_card.md`: model version, SHA-256 of the four IDX files (equal to data/recommendation-engine/README.md) and of the ONNX file, split sizes, seed, settings, library versions, test accuracy with a per-class table and confusion matrix, known limits (greyscale studio pictures, white garments, phone photos), the Fashion-MNIST citation (Xiao, Rasul and Vollgraf, 2017) and the MIT notice, and an honest status line: the 100-photo team evaluation of LLD 7.7 is NOT done, so the confidence threshold is the documented default 0.6 and `GARMENT_GUESS_ENABLED` must stay false for any pilot until it is done (LOI-9). A vitest test `workflow/gates/model_card.test.ts` fails if the ONNX file's SHA-256 differs from the card.
- CC6 (G4): no H&M data anywhere in this release; the committed ONNX file is trained on Fashion-MNIST only; `models.manifest.json` unchanged; manifest_check passes; the IDX files are not committed (git-ignored folder).

## Scope fence
Will NOT touch: apps/*, packages/*, docs/*, legal/*, supabase/*, jobs/*, models.manifest.json, anything H&M. Will NOT do: the worker service, Docker files, garment model v2, embeddings in the app.

## Glossary
- "preprocessing" is LLD 7.7: crop to the bounding box of alpha above 10%, composite on white, greyscale, invert, scale the longer side to 28 with Lanczos and centre on a black 28x28 canvas, divide by 255, shape 1x1x28x28 float32.

# Work Order WO-0031: training, evaluation, export, model card, card check
Action: execute (after WO-0030 is committed). Owner: ML and data maker. Checker: Spec QC + Model QC (Opus, fresh).
In scope: ml/recommendation-engine/garment/train.py, ml/recommendation-engine/garment/evaluate.py, ml/recommendation-engine/garment/export_onnx.py, ml/recommendation-engine/garment/model.py, ml/recommendation-engine/garment/model_card.md, ml/recommendation-engine/garment/tests/**, services/worker/models/garment-cnn-v1.onnx, workflow/gates/model_card.test.ts, workflow/evidence/R5/**
Instructions: read LLD 7.7 (network, augmentation, training, export, model card). Network: three 3x3 conv blocks (16, 32, 64 channels, ReLU, the first two followed by 2x2 max pooling), global average pooling, a dense layer of 32 units with ReLU (the 32 shape numbers), 10-way output; about 26,000 weights. Augmentation per LLD (small rotations, shifts, scaling, brightness and contrast, blur, random erasing). PyTorch CPU, Adam, cross-entropy with label smoothing 0.1, up to 30 epochs with early stopping on validation accuracy, fixed seed, time-box the full training to about 25 minutes of wall-clock (reduce epochs if needed and say so in the card). Training data path from SPARTA_DATA_ROOT_MNIST in workflow/local.env (IDX files only). Export per CC4 (opset recent enough for onnxruntime installed), keep the file under 1 MB. `evaluate.py` runs the ONNX file with onnxruntime on the 10,000 test pictures. Generate the card from the real run (script-generated numbers, not typed by hand), including SHA-256 of the data files (compute them; they must equal data/recommendation-engine/README.md) and of the ONNX file. Write workflow/evidence/R5/ logs of the train/evaluate runs (text). Add the vitest `workflow/gates/model_card.test.ts` (read the card's SHA-256 line and compare with the ONNX file's computed SHA-256 using node:crypto; fail on mismatch). Tests per CC2 (WO-0031 part: network shape and weight count, export check, evaluate on a tiny synthetic IDX pair, card-generation unit test). Counted lines under 450 (excluding the card, logs and the ONNX).
Completion conditions: CC1 to CC6.
