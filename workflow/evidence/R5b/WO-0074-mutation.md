# WO-0074 mutation proof (R5b)

Method: a scratch copy of the repository OUTSIDE the repo (rsync without `.git`, `node_modules`, `.next`; `node_modules` symlinked); the script `mutate.py` lives in the session scratchpad, not in the repository. One edit to one file per mutant, then `vitest run` over the unit suites of this work order (`apps/web/lib/server`, `apps/web/test-support`, `source.test.ts`, `workflow/gates/web_containment.test.ts`; integration suites excluded), then the file is restored. A mutant is KILLED when at least one test fails. Baseline of the copy: 0 failing. The S-rows are mutants of REAL application source (a new importer of the secret-key module added to a component in six import forms) against the importer pin in `source.test.ts`; the old pin (single-quoted `from` only) could not see S1 to S6 by construction, as its pattern matches `from '...'` only.

Result: 56 mutants, 56 killed, 0 survived. A first run showed that two edits had not applied (M03, M04: the pattern lacked a blank line) and that one mutant (M30) was killed only by a timing assumption of `stack-lock.test.ts` that was too tight (the take-over wait has up to 500 ms of slack). The test tolerance was widened (never narrowed) and a test for multi-line export-from was added; this table is the full re-run.
