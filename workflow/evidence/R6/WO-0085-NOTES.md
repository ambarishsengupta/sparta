## What was built
- `/catalogue` (`components/catalogue/CatalogueView.tsx`, `app/catalogue/page.tsx`): search by name or brand, filters category, brand, colour family and style (a fit, pattern or occasion tag; `Slim (fit)`), keyset pages of 40 by name then id with "Show 40 more", tiles with the tinted category illustration, name, brand, colour family, price through `lib/money.ts` (`formatPrice`), a "Choose" button and "View at source". Empty catalogue: a plain `role="status"` message and "Add my own". Only the newest request may change the screen (a counter), a failed read shows the fixed sentence and never an empty list.
- "View at source" (`SourceLink.tsx`): only for an `https:` address without a login in it, `target="_blank" rel="noopener noreferrer nofollow"`, nothing fetched. Shown on the tile and on the pre-filled form.
- Choosing a tile opens the existing `ItemForm` pre-filled (`catalogueStart`): catalogue name kept (FDD 13), stored colour, category, sub-type, fit, material, pattern, seasons, occasions; the drawing, "From the catalogue: <brand>, listed at <price>", a Size select when the item lists sizes, and an optional "Price paid" block (price of one piece, currency, date, store) at the end. Save: item with origin `catalogue`, `catalog_item_id`, `brand`, `size_value` (`lib/supabase/mapping.ts itemRow`), `item_added` event origin `catalogue`; when a price or a date was typed the WO-0081 purchase module records a purchase (WO-0081 rules: both price and a real, not-future date are then needed) and `purchase_recorded` with origin `catalogue` and nothing else. If the purchase fails after the item was saved, a retry reuses that item (never a second one).
- Repositories: `WardrobeRepository.catalogue` (`page(filter, after)`, `brands()`). Supabase: `catalog.catalog_items` through PostgREST with the session, `status = 'active'` asked for explicitly on top of the consumer policy, values inside `or(...)` double-quoted and escaped, wildcards escaped, taxonomy-checked filters, a cursor whose id is not a uuid ignored, rows the taxonomy cannot read skipped. Blocked repository fails it like the rest. Local (no-login) repository: see "Bundled demo catalogue".
- Onboarding (`OnboardingForm.tsx`): the single Continue button became three submit buttons after the questions, "Start from popular items" (`/catalogue`), "Add my own" (`/items/new`), "Skip" (`/`). The country, hemisphere and currency checks run before any of them (shown in the browser: without a country all three errors appear and nothing is sent).
- Thin-wardrobe message (FR-54): the "missing" notice in `OutfitsView` now has "Pick from the catalogue" next to the wardrobe link. The wardrobe header gets "Add from catalogue".
- Illustrated tiles: every wardrobe tile (`ItemCard`) draws `CategoryIllustration` tinted in the stored colour instead of the flat colour square, and the item page draws it above the form. `.swatch` got the paper background; `.art` (10rem) is new. No new colour, radius or font.
- Bundled SYNTHETIC demo catalogue for the browser-only prototype (`lib/demo-catalogue.ts`): 40 invented items (8 garments x 5 colours) under the 8 invented brands of the WO-0083 seed, ids `demo-0001..0040`, `DEMO_CATALOGUE_SYNTHETIC = true`, relative links so no "View at source" shows, no address literal (the strict no-network scan covers it). `LocalRepository` takes the list as a third constructor argument, so a test (and the empty state) can pass `[]`. The signed-in app never uses it.

## Deviations and open points
- Item images are not shown anywhere in the app today (`ITEM_SELECT` has no image paths), so "every item without an image" is every item: all tiles and the item page draw the illustration. When photo thumbnails are shown (not in this work order) the illustration is the fallback.
- "Style" is a single select of fit, pattern and occasion tags (glossary), not three controls.
- Brand filter lists up to 1,000 rows' brands (deduplicated); a larger catalogue would need a distinct query or a view (WO-0083 scope).
- Existing quirk, not changed: after a failed first submit, choosing a country fills hemisphere and currency but leaves their old error lines until the next submit (visible in desktop screenshot 2, "Choose your currency" under INR).
- The demo seed rows point at `http://127.0.0.1/...`, so "View at source" never shows in the demo; the https behaviour is proved by unit tests and the one-row browser check above.
- The 'Black running shorts' demo-wardrobe drawing looks like a vest (the WO-0084 Activewear shape); not touched (components/ui is read-only here).
- An unrelated problem seen once: the first update of a demo row's product link was gone a minute later (the demo seed had apparently been re-run by something else sharing the local database); repeating it worked.
